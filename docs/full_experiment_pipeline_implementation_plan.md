# 完整论文实验流水线工程施工计划

## 1. 文档目的

本文档是后续工程修改、实验执行和论文交付的统一施工依据。目标是将当前项目从“能够运行若干 JuPedSim 场景”完善为一套具备以下能力的实验系统：

- 输入数据可校验、可追溯；
- 画像、规划和仿真模块具有稳定的数据契约；
- 对照实验、消融实验和多随机种子实验可以批量执行；
- 每次运行都能还原代码、配置、数据和模型条件；
- 指标、统计检验、图表和论文表格可以自动生成；
- 无远程 LLM 和无外部数据时仍可运行最小验证流程；
- 最终实验可以由一条命令从配置生成完整结果包。

本文档只定义施工顺序和验收标准，不在此处提前决定实验结论。

## 2. 施工原则

1. **先固定契约，再拆分实现**：先确定输入输出格式，再拆分当前较大的仿真入口。
2. **先完成核心闭环，再增加训练流程**：主论文实验不应被可选的模型微调阻塞。
3. **一个实验单元一个目录**：轨迹、计划、画像、日志和元数据必须通过同一个 `run_id` 关联。
4. **配置是事实来源**：正式实验不得依赖只存在于命令历史中的参数。
5. **原始数据只读**：预处理结果写入 `data/processed`，不得覆盖原始数据。
6. **统计单位是独立运行**：不能把同一运行中的多个 agent 当作完全独立的重复实验。
7. **失败也要留记录**：失败原因、退出码和已产生的产物应写入 manifest。
8. **兼容现有入口**：施工期间保留 `src/*.py` 和 `scripts/*.ps1` 兼容入口，直至迁移完成。

- [x] 无 LLM 的 smoke 场景能在干净环境中完成；
- [x] 固定 seed 的重复运行具有可解释的一致性；
- [x] baseline、主方法、画像消融、路线消融和物理参数消融均有配置；
- [ ] 每个正式场景至少使用预先确定的多个 seed 独立运行；
- [x] 自动输出逐运行指标、聚合指标、置信区间、效应量和显著性检验；

## 4. 当前基础与缺口

### 4.1 当前已有能力

- 已建立 `src/jupedsim_mall` 包结构，并保留旧入口兼容脚本；
- 已有地图几何、入口出口和语义区域数据；
- 已有 mall、ATC、LLMob 画像来源；
- 已有 random、nearest、LLM exit-only 和 LLM semantic route 场景；
- 已有多 seed 重复运行、manifest、场景校验和 dry-run；
- 已有基础结果汇总、JSD 比较和 ATC 真实性评价；
- 已有轨迹 SQLite、计划 JSON 和画像 JSON 产物。

### 4.2 关键缺口

- 包结构已经建立，但仿真职责仍集中在 `simulation/runner.py`；
- 数据契约尚未覆盖地图、运行产物、指标表和模型调用记录；
- 输出仍以分散文件为主，缺少统一的 `run_id` 目录协议；
- 缺少完整的轨迹指标、区域密度、拥堵、停留和完成率提取；
- 缺少严格的统计检验、效应量、置信区间和多重比较控制；
- 缺少论文图表生成器和最终报告生成器；
- 缺少系统化测试、依赖锁定和正式实验前的冻结流程；
- 缺少离线 LLM 响应缓存，远程模型条件下的实验复现仍不充分；
- 缺少数据泄漏检查、异常运行排除规则和实验失败判定规则。

## 6. 总体依赖顺序

```text
基线冻结
  -> 环境与入口统一
  -> 数据契约
  -> 地图和数据预处理
  -> 画像统一
  -> 路线规划统一
  -> 仿真内核拆分
  -> 运行产物协议
  -> 实验矩阵与批量运行
  -> 指标提取
  -> 真实性与统计分析
  -> 图表和报告
  -> 试运行
  -> 正式实验与冻结交付
```

后续修改必须按该顺序推进。允许同一阶段内并行开发，但不得在上游契约未稳定时大规模实现下游分析。

## 11. 总控命令的最终目标

完整流水线最终应收敛到类似以下命令：

```powershell
# 环境和数据检查
python -m jupedsim_mall doctor
python -m jupedsim_mall data prepare --config configs/data/atc.json
python -m jupedsim_mall map validate --map data/map

python -m jupedsim_mall experiment prepare configs/matrices/thesis_main.json
python -m jupedsim_mall experiment run configs/matrices/thesis_main.json
python -m jupedsim_mall experiment resume configs/matrices/thesis_main.json

python -m jupedsim_mall analyze metrics --matrix configs/matrices/thesis_main.json

python -m jupedsim_mall analyze statistics --config configs/analysis/statistics.json
python -m jupedsim_mall report build --config configs/analysis/report.json

# 最终完整性检查
python -m jupedsim_mall experiment verify configs/matrices/thesis_main.json
```

最终可再提供一个 PowerShell 包装入口：

```powershell

```

该脚本只负责编排上述稳定 CLI，不重复实现 Python 业务逻辑。

## 12. 范围控制

核心施工期间暂不做以下事项，除非其成为论文明确研究问题：

- 不整包迁入外部 TIMB/Intent_simulated 工程；
- 不在仿真主循环中执行模型训练；
- 不为了增加代码量复制外部绘图脚本；
- 不在指标定义冻结前批量跑正式实验；
- 不用单次运行或挑选后的 seed 支撑统计结论；

- 不用手工编辑最终 CSV、图表或论文数字。
