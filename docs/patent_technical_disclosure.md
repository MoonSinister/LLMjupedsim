# 基于真实轨迹数据契约与大模型对齐的室内人群仿真方法技术交底书

> 文档用途：供专利代理人、科研管理人员和发明人沟通技术方案使用。本文不是最终权利要求书，具体保护范围应由专利代理师结合检索结果和申请策略确定。

## 1. 拟申请名称

一种基于真实轨迹数据契约与大模型对齐的室内人群仿真方法、系统、设备及存储介质。

备选名称：

- 一种面向室内大规模人群仿真的真实轨迹到行为规划样本转换方法及系统；
- 一种基于 SFT/DPO 样本构建和语义地图的室内行人行为仿真方法；
- 一种结合真实轨迹画像、大语言模型路径规划与物理仿真的室内人群模拟方法。

## 2. 技术领域

本发明涉及人群仿真、智能体行为建模、室内数字孪生、轨迹数据处理和大语言模型训练技术领域，尤其涉及一种将真实行人轨迹稳定转换为监督微调样本和偏好优化样本，并基于该样本训练或约束大模型生成室内人群行为计划，再驱动物理仿真引擎进行大规模室内人群模拟的方法。

## 3. 背景技术

现有室内人群仿真通常采用规则路由、最短路径、随机出口选择或预设 OD 流量等方式。此类方法能够在物理层面模拟避障、碰撞规避和出口通行，但存在以下问题：

1. 行人行为类型单一，难以表达通勤者、购物者、工作人员、访客等不同人群的偏好、速度、停留和区域访问差异。
2. 真实轨迹数据通常是连续坐标点序列，缺少与语义区域、行为意图、活动停留、出口选择相对应的稳定数据结构，难以直接用于大模型训练。
3. 大模型可生成自然语言或 JSON 形式的行为计划，但若缺少可验证的数据契约，容易出现区域不存在、出口非法、路径不可达、agent 缺失、格式不一致等问题。
4. 仅比较训练损失或离线路径分数，不能保证生成的行为计划在室内物理仿真中稳定执行，也不能保证群体行为分布接近真实轨迹。
5. 真实数据、训练样本、模型版本、仿真场景和分析结果之间缺少统一追溯机制，导致实验难以复现。

因此，需要一种将真实轨迹稳定转换为可训练、可校验、可追溯的行为规划样本，并与室内语义地图和物理人群仿真联动的方法。

## 4. 要解决的技术问题

本发明至少解决以下技术问题：

1. 如何把真实行人轨迹从连续坐标点稳定转换为包含画像、语义区域、活动、停留、出口和路线的结构化训练样本。
2. 如何同时构造适用于 SFT 的监督样本和适用于 DPO 的偏好样本，使大模型不仅学习输出格式，还学习更符合真实轨迹和室内可达约束的行为计划。
3. 如何根据真实轨迹生成可复现的人群种类画像，包括角色、速度、偏好区域、停留时间、历史线索和意图线索。
4. 如何将大模型生成的高层行为计划转换为物理仿真引擎可执行的 journey、stage 或 waypoint。
5. 如何在大规模室内场景中稳定执行多 seed、多场景、多画像来源和多路线策略的人群仿真实验。
6. 如何对仿真输出进行真实性评价和统计分析，判断仿真人群是否在分布上接近真实轨迹。

## 5. 技术方案概述

本发明提出一条端到端技术路线：

```text
真实轨迹数据
  -> 坐标标定与数据切分
  -> 轨迹事实提取
  -> 真值投影为行为计划 JSON
  -> 生成 SFT 样本和 DPO 偏好样本
  -> 训练或对齐路线规划大模型
  -> 根据画像和语义地图生成 agent 行为计划
  -> 转换为室内物理仿真 journey/stage
  -> 大规模人群仿真
  -> 指标提取、真实性评价和报告生成
```

其中，“真实轨迹到 SFT/DPO 样本的数据契约”是核心技术环节。该数据契约将真实轨迹、地图版本、坐标变换、人员分区、画像、可用出口、可用语义区域、目标行为计划、标签来源、质量标记和版本哈希统一封装，使训练样本和仿真实验能够稳定复现。

## 6. 系统组成

系统可包括以下模块。

### 6.1 真实轨迹接入模块

用于接收 ATC、LLMob 或其他真实室内轨迹数据。输入可以包括时间戳、人员标识、坐标、速度、朝向等字段。系统对人员标识进行哈希化处理，并保留原始数据文件的 SHA-256 指纹、数据来源、单位和导入时间。

### 6.2 坐标标定与地图语义化模块

用于将真实轨迹坐标转换到仿真地图坐标系。坐标变换配置至少包括尺度、旋转、平移、轴顺序和翻转参数。地图侧包含可行走几何、入口、出口、语义区域和候选出口约束。

语义区域可包括通道、店铺、餐饮区、扶梯、出入口、等待区等。每个区域具有唯一名称、世界坐标 polygon、区域类别和自然语言描述。

### 6.3 轨迹事实提取模块

用于从真实轨迹中提取可训练事实，包括：

- 起点、终点、持续时间、路径长度；
- 平均速度、速度分位数、低速比例；
- 区域访问序列、首次进入时间、停留时间、回访次数；
- 入口和出口映射；
- 轨迹异常原因，例如越界、跳跃、区域歧义或出口缺失。

### 6.4 人员分区与泄漏审计模块

用于按人员级别将真实轨迹稳定切分为训练、调参和评估集合。一个实施方式中，使用 `sha256(person_id)` 前若干位对固定桶数取模，桶 0 作为 evaluation，桶 1 作为 tuning，其余作为 train。系统检查不同分区人员 ID 不重叠，且同一人员派生的窗口、画像、候选和统计量不跨分区。

### 6.5 行人画像生成模块

用于根据真实轨迹或内置规则生成 `AgentProfile`。画像字段包括：

- `profile_id`：画像唯一标识；
- `role`：commuter、shopper、staff、visitor 等；
- `preferences`：偏好语义区域或行为；
- `desired_speed_mps`：期望速度；
- `default_wait_seconds`：默认停留时间；
- `history_hint`、`intent_hint`、`memory_hint`：供大模型规划使用的行为线索；
- `source` 和 `metadata`：记录画像来源和预处理信息。

画像可来自真实轨迹聚合、LLMob 活动记录、内置商场人群模板或其组合。

### 6.6 行为计划真值投影模块

用于将连续轨迹投影为大模型可学习的 `AgentRoute`。投影流程包括：

```text
连续轨迹点
  -> 坐标变换
  -> 语义区域归属判断
  -> 时间去重与区域序列压缩
  -> 可达性约束修正
  -> 活动与停留标签生成
  -> 最终出口映射
  -> 行为计划 JSON
```

`AgentRoute` 包括 agent 标识、最终出口索引、中间语义区域序列、活动列表、自然语言意图、期望速度、规划器来源和 fallback 原因。

### 6.7 SFT 样本构建模块

用于把画像、地图上下文、可用区域、候选出口和目标行为计划封装成监督微调样本。样本采用 chat messages 格式：

```json
{
  "example_id": "sha256:...",
  "messages": [
    {"role": "system", "content": "版本化系统提示词"},
    {"role": "user", "content": "agent 画像、出生区域、候选出口、语义地图上下文"},
    {"role": "assistant", "content": "严格 JSON 行为计划"}
  ]
}
```

该样本用于训练大模型稳定输出符合 schema 的室内行为计划。

### 6.8 DPO 偏好样本构建模块

用于为同一 prompt 生成多个候选行为计划，并构造成 chosen/rejected 偏好对。候选来源可包括：

- 真实轨迹投影候选；
- 教师模型候选；
- 规则规划器候选；
- 受控扰动候选，例如次优出口、过长路径、画像不匹配行为或不可达区域。

系统先执行硬校验，再执行软评分。硬校验包括 JSON/schema 合法性、agent 完整性、区域存在性、出口合法性、可达性和数值范围。软评分可综合路线相似性、出口准确性、停留合理性、画像匹配度、流动效率和格式完整性。

DPO 样本格式为：

```json
{
  "example_id": "sha256:...",
  "prompt": [{"role": "system", "content": "..."}, {"role": "user", "content": "..."}],
  "chosen": [{"role": "assistant", "content": "较优 JSON 行为计划"}],
  "rejected": [{"role": "assistant", "content": "较差 JSON 行为计划"}],
  "preference": {
    "chosen_score": 0.91,
    "rejected_score": 0.63,
    "score_gap": 0.28,
    "scorer_version": "plan_scorer_v1"
  }
}
```

### 6.9 大模型训练与服务模块

用于基于 SFT 样本和 DPO 样本训练路线规划大模型。一个实施方式中，使用 QLoRA 进行 SFT，再以 SFT adapter 为基础进行 DPO。训练后的模型通过 OpenAI-compatible API 提供服务，使仿真模块无需直接加载模型权重。

### 6.10 行为规划模块

用于在仿真运行时，根据 agent 画像、出生区域、候选出口和语义地图调用模型，生成每个 agent 的路线和活动计划。系统支持 LLM semantic route、LLM exit-only、nearest baseline、random baseline 和 replay planner。

### 6.11 物理仿真执行模块

用于将高层行为计划转换为 JuPedSim 或其他室内人群仿真引擎可执行的 journey/stage/waypoint。该模块支持：

- 分批出生和最大活跃人数限制；
- 活动等待；
- 路由 waypoint 插入；
- 拥堵检测和重路由；
- agent 生命周期 TTL；
- 轨迹 SQLite 输出；
- lifecycle events JSONL 输出。

### 6.12 指标分析与真实性评价模块

用于从仿真输出中提取 agent-level 和 run-level 指标，并与真实轨迹参考分布比较。指标包括完成率、旅行时间、路径长度、平均速度、低速比例、等待时间、区域访问、出口分布、局部密度、拥堵、重路由和 TTL 移除率。

真实性评价可使用 Jensen-Shannon Divergence、Wasserstein distance、KS statistic 或其组合。一个实施方式中，综合真实性差异为：

```text
D_realism =
  w_T * JSD_travel_time
  + w_L * JSD_path_length
  + w_V * JSD_speed
  + w_R * JSD_region_visit
  + w_S * JSD_slow_ratio
```

## 7. 关键创新点

### 7.1 真实轨迹到行为计划样本的稳定数据契约

本发明将连续轨迹、语义地图、人员分区、坐标变换、画像、输出 schema、标签来源和质量标记绑定到同一个样本契约中，使真实轨迹能够稳定转换为可用于大模型训练的结构化行为计划样本。

### 7.2 同源构建 SFT 与 DPO 样本

同一真实轨迹窗口既可生成监督真值计划，也可生成多个候选计划并构造偏好对。由此模型同时学习“如何按规定格式输出”和“哪种行为计划更符合真实轨迹、画像和空间约束”。

### 7.3 人员级分区与泄漏审计

系统在轨迹窗口、画像生成、候选生成和统计评价之前完成稳定人员分区，并自动检查分区交集，避免真实轨迹数据在训练、调参和评价之间泄漏。

### 7.4 画像、语义地图与物理仿真的闭环联动

本发明不是仅输出离线路线，而是将大模型生成的高层行为计划转换为物理仿真可执行对象，并通过轨迹、事件和指标反馈评价其群体行为效果。

### 7.5 可复现的大规模实验矩阵

系统使用场景配置、矩阵计划、seed 冻结、run manifest、文件哈希和模型登记信息管理仿真实验，使多方法、多画像、多 seed、大规模室内场景对比能够复现。

## 8. 有益效果

与现有技术相比，本发明具有以下有益效果：

1. 将真实轨迹转换为可训练、可校验、可复现的大模型行为规划样本，减少人工标注成本。
2. 能生成不同类型行人的画像和行为计划，提高室内人群仿真的异质性和可解释性。
3. 通过 schema 校验、可达性校验和 fallback 机制，提高大模型路线规划进入物理仿真的稳定性。
4. 通过 DPO 偏好样本，使模型不仅学习格式，还学习更符合真实轨迹分布和室内空间约束的路线策略。
5. 通过真实分布评价和多 seed 统计分析，使仿真结果能够与真实人群行为进行群体层面对比。
6. 通过 manifest、hash 和模型登记机制，提高训练与仿真实验的可追溯性。

## 9. 具体实施例

### 实施例一：基于 ATC 真实轨迹的训练样本构建

系统读取 ATC 单日轨迹数据，字段包括时间、人员 ID、毫米坐标、速度和朝向。系统将毫米坐标转换为米制坐标，并根据配置进行旋转和平移，使其落入室内语义地图坐标系。

对每个合格人员轨迹，系统按时间窗口提取轨迹事实，并判断每个轨迹点所属语义区域。连续重复区域被压缩为区域访问序列，停留超过阈值的区域生成 activity。轨迹终点映射为候选出口。若轨迹点越界或出口无法映射，则样本标记为失败原因而非静默修补。

系统生成 SFT 样本，其中 user 消息包含画像、候选出口和语义区域，assistant 消息包含 `AgentRoute` JSON。系统进一步生成多个候选计划，根据 schema 合法性、可达性、出口匹配、区域序列相似度和停留合理性评分，形成 DPO 的 chosen/rejected 样本。

### 实施例二：基于训练模型的室内人群规划

在仿真运行时，系统为每个出生入口生成多个 agent。每个 agent 采样一个画像，包括角色、偏好、速度和默认停留时间。系统将若干 agent 打包，请求训练后的大模型输出行为计划。模型返回 JSON 后，系统校验 agent 是否齐全、出口是否属于候选出口、区域是否存在、速度和等待时间是否在范围内。

对于合法计划，系统创建语义 journey；对于缺失或非法计划，系统按 nearest 或 random baseline fallback。全部计划写入 `plans.json`，并记录 prompt 版本、模型名、缓存键和 fallback 比例。

### 实施例三：大规模室内场景仿真与评价

系统读取商场可行走几何、入口、出口和语义区域，在 JuPedSim 中创建仿真对象。agent 按计划分批出生，在到达语义活动区域后执行等待，再前往下一区域或最终出口。若 agent 长时间低速或卡住，系统触发重路由或等待释放；若超过生命周期上限，标记为 TTL 移除。

仿真结束后，系统输出轨迹数据库、事件日志、计划文件、运行清单和指标文件。系统从轨迹中计算路径长度、旅行时间、速度、低速比例、区域访问、密度、拥堵和出口分布，并与 ATC 参考分布计算 JSD，用于评价仿真人群行为真实性。

## 10. 可替代实施方式

1. 物理仿真引擎不限于 JuPedSim，也可替换为其他支持行人运动、出口和轨迹输出的仿真器。
2. 大模型可为本地模型、云端模型、蒸馏模型或规则与模型混合规划器。
3. SFT/DPO 可替换为其他监督学习、偏好优化或强化学习方法，但仍使用相同数据契约。
4. 真实轨迹来源不限于 ATC 或 LLMob，也可使用商场 Wi-Fi、蓝牙、视觉跟踪、闸机或 UWB 数据。
5. 真实性评价指标可使用 JSD、Wasserstein、KS、Earth Mover Distance 或多指标加权组合。
6. 画像类型可根据场景调整，例如乘客、患者、工作人员、参观者、应急疏散人员等。
